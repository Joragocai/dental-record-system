## Failure handling
- No Supabase invite received: inspect staging Supabase Auth email invitation settings, rate limits and redirect allowlist, without sharing secrets.
- Invitation shows invalid redirect: correct the **exact** staging Redirect URL in Supabase; do not weaken CORS, Auth or TLS.
- Invite in `sending` or `reconciliation_required`: STOP. A potentially created provider user may exist. Manually compare the provider UUID/email with the DB in an authorized private admin session and document reconciliation before any resend. Do not auto-delete an unverified identity or flip DB statuses blindly.
- Activation fails: verify confirmed-email status, exact provider subject and pending link. Do not bypass activation by inserting an active app_user.
- Migration fails: stop deployment and diagnose; do not reset/drop tables or apply SQL manually.
- If the user elects to defer manual QA, preserve these steps for Phase 19. Implementation still requires automated role/ownership/database-integrity tests before moving beyond 14A.
