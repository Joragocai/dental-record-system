C. ANNUAL PATIENT CODE ALLOCATION

Implement a PostgreSQL-safe annual patient-code allocation mechanism that preserves approved V1 visible semantics.

Requirements:
- no `MAX(...) + 1`;
- no row-count-based allocation;
- safe under concurrent allocation;
- transactional/atomic;
- year reset behavior preserved;
- patient code remains separate from the UUID primary key;
- uniqueness enforced at the database level at the correct scope;
- do not silently change the code format.

Use the smallest maintainable mechanism.

A counter table plus atomic PostgreSQL upsert/RETURNING logic is acceptable if it fits the verified V1 semantics.

Do not generalize the counter abstraction beyond immediate/future justified use.

If the correct scope of numbering is genuinely unresolved in the source-of-truth docs and V1 behavior does not answer it, STOP and report the open decision instead of guessing.
